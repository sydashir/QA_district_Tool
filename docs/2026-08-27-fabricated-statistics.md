# Fabricated statistics on live healthcare pages

**For Syed. Written 2026-08-27. NOT an audit finding — do not put this in the QA report.**

> **OUTCOME, 2026-08-28: raised and knowingly accepted.** Syed reviewed this and decided the
> fallback values stay as they are. No action follows from this document and no check was built to
> flag the fabricated figures. It is kept — not deleted — as the record that the behaviour was
> found, understood and accepted deliberately rather than overlooked. If anyone later asks whether
> we knew, the answer is yes, and this is when.

This is an editorial and possibly compliance matter, not a defect row. It needs a conversation with
the client, not a ticket.

**How we found it: by reading the source code of their own content tool**, during an investigation
into whether we could build a sheet-versus-live comparison. This is not inferred from patterns in
the pages, and it is not a guess about how the numbers look. It is what the code does, and the
file and line numbers are below so anyone can check.

Repository: the GeoData Fetcher, `services/geo_data_service.py`, function `write_location_data`.

---

## What the code does when a statistic is missing

The function's stated rule is that a geo cell must never be left blank. When the real value is
missing or zero, it substitutes something else and writes that instead. The substitutions are not
labelled on the page in any way — they render exactly like a real figure.

| What is missing | What gets published instead | Line |
|---|---|---|
| **Number of facilities** | **A random number, 1 or 2** — `random.randint(1, 2)` | `:1788`, and again `:1834`, `:1861` |
| **Population with addiction** | **Overdose deaths × 25** | `:1809` (also `:2544`, commented "SAMHSA multiplier estimate") |
| — or, failing that | **1.5% of total population** | `:1813` |
| **Year of the data** | **`2024`, hardcoded** — in a variable named `current_year`, with the comment *"use current year"* | `:1774` |
| **A date range** | **`"2023-2024"`**, built from that same hardcoded year | `:1796` |
| **Facility rating** | **`4.0`** | `:1776` |
| **Review count** | **`10`** | `:1778` |
| **Anything else** | the literal text **`Not found`** | `:1769`, `:1821`, `:1848` |

---

## Why each of these matters

**The facility count is the most serious.** A page that says *"there are 2 treatment centers in
[town]"* may be publishing a number generated by a random number generator. There is no way for a
reader — or for the client — to tell which counts are real and which are not. On a page whose
purpose is helping someone find treatment, that is a factual claim about healthcare availability.

**The addiction-population figure is an estimate presented as a measurement.** Multiplying overdose
deaths by 25 is a recognised epidemiological rule of thumb, and the code comments name SAMHSA. But
the page does not say it is an estimate, does not name the method, and does not cite the source. It
reads as a count.

**The year is stale and mislabelled.** The variable is called `current_year` and the comment says
"use current year", but the value is fixed at `2024`. It is now 2026. Any page that fell back to
this default is presenting two-year-old framing as current, and the date range `2023-2024` is
built from the same constant.

**`Not found` is a string, not a blank.** Where no substitution rule applies, the literal text
`Not found` is written into the cell. If that cell feeds a sentence, the page renders something
like *"there are Not found treatment centers in Fresno County"*. We are building a check for this
one, because it is visible and unambiguous.

---

## Two things worth saying plainly

1. **Their own QA cannot catch any of this.** The Fetcher's quality checks test whether a cell is
   empty or zero. Every substitution above is a non-empty, non-zero value, so all of them pass its
   checks cleanly. Nobody is ignoring a warning — there is no warning to ignore.

2. **We do not know how many pages are affected.** The substitution only fires when the real value
   is missing, and we cannot tell from outside which values were missing. It could be rare. It could
   be widespread on the geo pages, which is where the thin data is. Establishing that would mean
   comparing the sheets against the sources, which is a separate piece of work.

---

## What we are proposing to do about it

**In the tool: only the visible part.** We will detect the literal `Not found` string and the
obviously-defaulted values where they reach a page, because those are unambiguous. We will not try
to flag a facility count as fabricated — a real small town might genuinely have one or two
treatment centres, and a check that cannot tell the difference would accuse correct pages.

**Outside the tool: this is a decision for the client.** The options are theirs, not ours — remove
the fallbacks so a missing statistic renders as nothing, label estimates as estimates, or accept
them knowingly. What matters is that the decision is made deliberately rather than by a default
written into a function two years ago.

We would suggest raising it as something we noticed while working on the audit, because that is
exactly what happened.
